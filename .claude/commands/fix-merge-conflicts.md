# Fix merge conflicts

Work from the repository root. If this is not a git repository, stop and say so.

Do not ask questions — pick sensible defaults and explain them in the summary. Do not push and
do not tag; commit locally only.

## Plan

1. Find the conflicts: `git status --porcelain` plus a search for conflict markers.
2. Resolve per file, preserving both sides' intent where they are compatible. Where they are
   mutually exclusive, keep the variant that type-checks and preserves the existing public API.
   - `pnpm-lock.yaml` / `uv.lock`: do not hand-merge. Take one side, then regenerate
     (`pnpm install`, `uv lock`).
   - `backend/openapi.json` and `frontend/src/lib/api/generated/`: never hand-merge either.
     Take either side and regenerate: `uv run dump-openapi` then
     `pnpm --filter web generate:api`.
   - `routeTree.gen.ts`: generated by the Start plugin — regenerate rather than merge.
   - Config files: keep the union of the safe settings.
3. Validate with the real gates: `pnpm verify`, then in `backend/`: `ruff`, `mypy`,
   `lint-imports`, `pytest`.
4. Stage the resolved files and commit as `chore: resolve merge conflicts`.

Keep the edits minimal — no reformatting of untouched code. If a resolution is ambiguous and
blocks the build, prefer the variant that compiles and passes the tests, and flag it in the
summary.
